# 前端开发

## 组件化

组件化是把界面拆成独立、可复用的组件，每个组件管理自己的结构（HTML）、样式（CSS）和行为（JS）。这是现代前端框架的基石思想。

### 为什么需要组件化

- **复用性**：按钮、表单、导航栏等通用部件只写一次，到处使用。
- **可维护性**：每个组件职责单一，改一处不影响全局。
- **协作效率**：团队可以并行开发不同组件。
- **可测试性**：组件边界清晰，容易单独测试。

### React 组件

React 现代写法是**函数组件 + Hooks**：

```jsx
function UserCard({ user, onFollow }) {
  const [following, setFollowing] = useState(false);

  const handleClick = () => {
    setFollowing(!following);
    onFollow?.(user.id);
  };

  return (
    <div className="user-card">
      <img src={user.avatar} alt={user.name} />
      <h3>{user.name}</h3>
      <button onClick={handleClick}>
        {following ? "已关注" : "关注"}
      </button>
    </div>
  );
}
```

- **props**：父组件传给子组件的只读数据。
- **state**：组件内部可变的状态，变化触发重新渲染。
- **useState**：声明状态和更新函数。
- **useEffect**：处理副作用（请求、订阅、DOM 操作）。

### Vue 组件

Vue 用**单文件组件（SFC）**，模板、脚本、样式写在一个 `.vue` 文件里：

```vue
<template>
  <div class="user-card">
    <h3>{{ user.name }}</h3>
    <button @click="toggleFollow">
      {{ following ? "已关注" : "关注" }}
    </button>
  </div>
</template>

<script setup>
import { ref } from 'vue'

const props = defineProps({ user: Object })
const following = ref(false)

function toggleFollow() {
  following.value = !following.value
}
</script>

<style scoped>
.user-card { padding: 16px; border: 1px solid #eee; }
</style>
```

### 组件通信

- **父 → 子**：props 传递。
- **子 → 父**：回调函数 / 自定义事件。
- **跨层级共享**：Context（React）/ Provide-Inject（Vue）/ 全局状态库。
- **兄弟组件**：提升 state 到公共父组件。

### 组件设计原则

- 单一职责：一个组件只做一件事。
- 容器组件 vs 展示组件：容器管数据，展示只管渲染。
- 组合优于继承：用 props、children（插槽）组合能力。
- 避免过深嵌套：嵌套太深难以维护。

## 状态管理

状态（state）是应用中会变化的数据，比如购物车商品、登录用户、页面 loading。组件多了以后，靠 props 层层传递会非常混乱，于是有了状态管理方案。

### 为什么需要状态管理

- 多个组件共享同一份数据（如购物车）。
- 状态更新逻辑复杂（异步、并发）。
- 需要跟踪状态变化的来源，方便调试。

### React 生态：Redux / Zustand / Context

**Redux** 的核心思想是**单向数据流**：

```
View → dispatch(action) → reducer(state, action) → new state → View
```

```js
// action
{ type: 'cart/add', payload: { id: 1 } }

// reducer（纯函数：相同输入必然相同输出）
function cartReducer(state, action) {
  switch (action.type) {
    case 'cart/add':
      return { ...state, items: [...state.items, action.payload] };
    default:
      return state;
  }
}
```

- **action**：描述"发生了什么"的普通对象。
- **reducer**：纯函数，根据 action 计算新状态，不能直接改旧状态。
- **store**：保存状态，提供 dispatch 和 subscribe。
- Redux Toolkit 是官方推荐写法，简化了大量样板代码。

**Context**：React 内置的跨层级传值方案，适合主题、语言、登录态这种"低频但深"的数据。高频变化的数据用 Context 会导致整棵树重渲染。

**Zustand**：轻量级状态库，直接改 state，模板代码少，现在是 React 社区的热门选择。

### Vue 生态：Pinia

Pinia 是 Vue 3 官方推荐的状态库（Vuex 的继任者）：

```js
import { defineStore } from 'pinia'

export const useCartStore = defineStore('cart', {
  state: () => ({ items: [] }),
  getters: {
    total: (state) => state.items.reduce((s, i) => s + i.price, 0),
  },
  actions: {
    add(item) { this.items.push(item) },
  },
})
```

Pinia 天然支持组合式 API、TypeScript 友好，比 Vuex 简单很多。

### 状态管理的选择建议

| 场景 | 方案 |
|---|---|
| 简单的跨层级传值 | Context / Provide-Inject |
| 中大型应用、复杂业务状态 | Redux Toolkit / Pinia |
| 轻量、快速上手 | Zustand |
| 服务端状态（请求缓存） | React Query / SWR / TanStack Query |

**重要认知**：不是所有状态都要进全局 store。只在多个组件真正共享时才需要全局状态，局部状态留在组件里即可。

## 响应式设计

响应式设计让网页在不同屏幕尺寸（手机、平板、电脑）上都能良好显示。核心思路是"布局跟着视口走"。

### CSS 媒体查询

```css
/* 基础样式：手机优先 */
.container {
  display: grid;
  grid-template-columns: 1fr;
}

/* 平板：>= 768px 两列 */
@media (min-width: 768px) {
  .container {
    grid-template-columns: repeat(2, 1fr);
  }
}

/* 桌面：>= 1200px 四列 */
@media (min-width: 1200px) {
  .container {
    grid-template-columns: repeat(4, 1fr);
  }
}
```

**移动优先（mobile-first）**：先写手机样式，再用 `min-width` 逐级增强，是业界主流做法。

### 弹性布局 Flexbox

Flexbox 适合一维布局（一行或一列）：

```css
.nav {
  display: flex;
  justify-content: space-between;  /* 主轴对齐 */
  align-items: center;             /* 交叉轴对齐 */
  gap: 16px;                       /* 间距 */
  flex-wrap: wrap;                 /* 允许换行 */
}
```

### 网格布局 Grid

Grid 适合二维布局（行+列）：

```css
.grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
  gap: 16px;
}
```

`auto-fit + minmax` 组合可以自动适配列数，是响应式网格的经典写法。

### 相对单位

- **rem**：相对根元素字体大小，适合全局缩放。
- **em**：相对父元素字体大小。
- **%**：相对父元素。
- **vw / vh**：相对视口宽高。
- **clamp()**：`font-size: clamp(14px, 2vw, 20px)`，设置一个随视口平滑变化的上限下限。

### 图片与多设备适配

```html
<picture>
  <source srcset="img-large.webp" media="(min-width: 1200px)">
  <img src="img-small.webp" alt="示例图片" loading="lazy">
</picture>
```

- `srcset` 按设备宽度加载不同分辨率的图片。
- `loading="lazy"` 懒加载，滚动到附近才加载，节省流量。

## 浏览器工作原理（常考）

理解浏览器渲染对前端性能优化很重要：

```
HTML → DOM 树     CSS → CSSOM
        合并 → 渲染树 → 布局（Layout）→ 绘制（Paint）→ 合成（Composite）
```

- **重排（reflow/layout）**：几何属性变化（宽高、位置），成本最高。
- **重绘（repaint）**：只改变外观（颜色、背景），成本中等。
- **合成（composite）**：只动 transform/opacity，用 GPU 合成，成本最低。

性能优化方向：减少重排、多用 transform 做动画、`will-change` 提示浏览器、`content-visibility` 跳过屏幕外渲染。

## 前端性能优化清单

1. **资源层面**：压缩 JS/CSS、图片用 webp/avif + 懒加载、CDN 加速静态资源。
2. **加载层面**：代码分割（Code Splitting）、按需加载路由组件、`defer`/`async` 加载脚本、HTTP/2 多路复用。
3. **渲染层面**：减少 DOM 深度、避免频繁操作 DOM、用 `requestAnimationFrame` 做动画、虚拟列表渲染大数据。
4. **缓存层面**：浏览器缓存（Cache-Control）、Service Worker 做 PWA 离线缓存。
5. **度量层面**：关注 LCP（首屏最大内容）、FID/INP（交互延迟）、CLS（布局偏移）等 Web Vitals 指标。
