# 算法复杂度分析

算法复杂度是衡量算法好坏的数学工具，分为**时间复杂度**和**空间复杂度**。它回答的问题是："当输入规模变大时，这个算法会变慢/变占内存多少倍？"

## 大 O 表示法

大 O 表示法（Big-O Notation）描述算法运行时间**随输入规模 n 增长的趋势**，忽略常数和低阶项。

### 核心思想

- 只关注**增长趋势**，不关心绝对耗时。
- 常数因子不影响渐进趋势：`3n` 和 `100n` 都是 O(n)。
- 只保留最高阶项：`n² + 3n + 5` 是 O(n²)。

```text
T(n) = 2n² + 3n + 5  →  O(n²)
T(n) = 10n + 100     →  O(n)
T(n) = 5             →  O(1)
```

### 为什么要忽略常数

因为当 n 足够大时，最高阶项完全主导。比如 n = 100 万时，`n²` 是 `10^12`，`3n` 只是 `3×10^6`，低阶项和常数的影响可以忽略不计。

### 常见复杂度对比

| 复杂度 | 名称 | n=10 | n=100 | n=10⁶ |
|---|---|---|---|---|
| O(1) | 常数 | 1 | 1 | 1 |
| O(log n) | 对数 | ~3 | ~7 | ~20 |
| O(n) | 线性 | 10 | 100 | 10⁶ |
| O(n log n) | 线性对数 | ~33 | ~700 | ~2×10⁷ |
| O(n²) | 平方 | 100 | 10⁴ | 10¹² |
| O(2^n) | 指数 | 1024 | 不可行 | 不可行 |

**直觉**：n 从 10 到 10⁶（放大 10 万倍），O(1) 不变，O(log n) 只多 6 倍多，O(n) 变 10 万倍，O(n²) 变 100 亿倍。所以**算法复杂度才是决定程序能不能撑住大数据的根本**。

## 如何分析一个算法的时间复杂度

### 1. 基本规则

- **顺序**：多个操作相加，取最高阶。`O(n) + O(n²) = O(n²)`。
- **循环**：一层循环通常 O(n)，嵌套两层 O(n²)。
- **分支**：取分支中最大的那个。

```python
# 两层嵌套循环 → O(n²)
for i in range(n):
    for j in range(n):
        do_something()
```

### 2. 对数复杂度从哪来

每次规模减半的操作（二分查找、分治、倍增）产生 O(log n)：

```python
# 每次循环 i 翻倍 → 循环次数 ~log2(n) → O(log n)
i = 1
while i < n:
    i *= 2
```

### 3. 均摊分析

有些操作偶尔很贵、但平均很便宜。动态数组扩容就是典型例子：

- 每次 append 到容量满时扩容并拷贝，单次最坏 O(n)。
- 但均摊下来，每次 append 成本 O(1)。

```python
lst = []          # 容量满时扩容
for x in range(n):
    lst.append(x)  # 均摊 O(1)
```

**均摊分析**是理解"动态数组、哈希表扩容、双端队列"性能的关键。

### 4. 递归的时间复杂度

递归用**递推公式**分析。以归并排序为例：

```text
T(n) = 2·T(n/2) + O(n)
```

规模减半、分成两个子问题、合并成本 O(n)。这个递推解出来是 **O(n log n)**。

**主定理（Master Theorem）**用于解形如 `T(n) = a·T(n/b) + O(n^d)` 的递推：

| 条件 | 结果 |
|---|---|
| d > log_b(a) | T(n) = O(n^d) |
| d = log_b(a) | T(n) = O(n^d log n) |
| d < log_b(a) | T(n) = O(n^(log_b(a))) |

例：归并排序 a=2, b=2, d=1，`d = log₂2 = 1` → O(n log n)，一致。

## 常见算法的复杂度速查

### 排序

| 算法 | 平均 | 最坏 | 空间 | 稳定 |
|---|---|---|---|---|
| 冒泡/选择/插入 | O(n²) | O(n²) | O(1) | 冒泡/插入稳定 |
| 快排 | O(n log n) | O(n²) | O(log n) | 不稳定 |
| 归并 | O(n log n) | O(n log n) | O(n) | 稳定 |
| 堆排 | O(n log n) | O(n log n) | O(1) | 不稳定 |

### 查找

| 算法 | 复杂度 | 条件 |
|---|---|---|
| 线性查找 | O(n) | 无序 |
| 二分查找 | O(log n) | 有序数组 |
| 哈希查找 | 平均 O(1) | 哈希表 |
| BST 查找 | 平均 O(log n)，最坏 O(n) | 二叉搜索树（平衡后 O(log n)） |

### 图

| 算法 | 复杂度 |
|---|---|
| DFS/BFS | O(V + E) |
| Dijkstra | O((V+E) log V)（堆优化） |
| Floyd | O(V³) |
| Kruskal 最小生成树 | O(E log E) |

## 空间复杂度

空间复杂度指算法运行需要的**额外内存**（不包括输入本身），同样用大 O 表示。

### 常见空间开销

- O(1)：只用几个临时变量。
- O(n)：存了和输入规模同级的辅助数组。
- O(n²)：二维矩阵。

```python
# O(n)：复制了一份数组
def copy(arr):
    return arr[:]           # 新数组大小 n

# O(1)：原地交换
def swap(a, b):
    tmp = a                 # 常数空间
    a, b = b, tmp
```

### 递归栈空间

递归的每一层调用都占栈空间，深度 d 就是 O(d) 空间。例：

- 二分查找递归版：O(log n) 栈空间。
- 深度优先遍历链状树：最坏 O(n)。

**尾递归**不会减少栈空间（除非编译器优化），这是很多新手误解。

## 空间换时间 / 时间换空间

工程上经常在两者间权衡：

### 空间换时间（最常见）

- **缓存**：把计算结果存起来（Redis、lru_cache），用内存换重复计算的耗时。最经典的例子。
- **哈希表**：把 O(n) 查找降到 O(1)，代价是内存。
- **前缀和**：先算好前缀和数组，区间求和从 O(n) 降到 O(1)。
- **预处理**：静态数据提前排好序/建好索引。

```python
from functools import lru_cache

@lru_cache(maxsize=128)     # 用空间换时间
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)   # 从 O(2^n) 降到 O(n)
```

### 时间换空间

- 数据流场景：不能存全量数据时用单遍扫描、滑动窗口。
- 外部排序：内存装不下，用多路归并，拿时间换内存。

### 权衡判断

- 内存便宜、时间贵 → 优先空间换时间。
- 内存紧张（嵌入式、大数据流）→ 优先时间换空间。
- 面试和工程里，绝大多数优化是"空间换时间"。

## 复杂度分析的工程意义

1. **预判性能**：写代码前先估算复杂度，n 到百万级 O(n²) 基本不可行。
2. **选择数据结构**：需要频繁查找 → 哈希表（O(1)）；需要有序 → 平衡树（O(log n)）；需要 FIFO → 队列。
3. **解释瓶颈**：线上慢，先看是不是某个 O(n²) 或 O(n³) 的循环。
4. **评估优化效果**：把 O(n²) 改成 O(n log n)，n 百万级时性能提升几千倍。

### 复杂度 vs 实际性能

复杂度是"趋势"，实际性能还受常数、缓存、IO、语言实现影响：

- 快排理论最坏 O(n²)，但实际通常比堆排（严格 O(n log n)）快，因为常数小、缓存友好。
- 小规模数据（n < 100）可能 O(n²) 的插入排序比 O(n log n) 的快排更快，很多内置排序对小区间切到插入排序。

**结论**：先按复杂度选算法，再结合常数和实际场景微调，两者都要懂。

## 面试中的复杂度问题

- "这段代码复杂度是多少？" → 看循环嵌套和递归。
- "还能更快吗？" → 先看有没有重复计算（→ 哈希/DP）、有没有必要排序（→ 换数据结构）。
- "为什么内置排序这么快？" → 常数优化 + 混合策略（Timsort、DualPivotQuicksort）。
- "刷题时" → 每题先写暴力（复杂度可能 O(2^n)/O(n²)），再优化到 O(n log n) 或 O(n)。
